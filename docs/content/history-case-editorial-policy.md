# 党史案例编审规范

## 发布原则

问道毛选只检索 `verification.status` 为 `cross-checked` 且 `review.status` 为 `source-reviewed` 或 `editor-approved` 的案例。AI 生成内容只能作为候选草稿，不能自行改为可发布状态。

每个发布案例必须同时具备：

1. 毛选原文或其他直接文献的精确篇名、文件名和段落锚点。
2. 共产党员网或中央党史和文献研究院等权威党史资料对历史背景或结果的核对。
3. 分别覆盖 `challenge`、`actions` 和 `outcome` 的证据声明。
4. 明确的现代迁移方法和不可照搬边界。
5. 在 `data/history-source-review.json` 中存在明确的审核批次记录。

## 审核状态

- `draft`：候选内容，未完成史料核验，不进入检索。
- `source-reviewed`：已核对本地原文、权威党史、引用映射和类比边界；只代表史料审核，不代表人工终审。
- `editor-approved`：经过可识别的人工编辑终审，必须使用 `reviewerType=human-editor`。
- `rejected`：存在无法消除的史料、因果、引用或类比问题。

## 编写规则

- 一个案例只回答一个核心问题，不按文章机械生成案例。
- 把史料直接记载、编辑概括和现实迁移分开书写。
- 不把时间先后写成因果关系，不把多方共同结果归功于单一措施。
- 结果不确定或存在争议时必须降低表述强度，并保留不同材料。
- 必须记录失败、代价、限制和不适用条件，禁止只写成功叙事。
- 不补写史料没有提供的对话、动机、数字、人物心理或行动细节。
- 军事、政治和阶级斗争经验不得直接映射为现代人际关系中的敌我判断。

## 编审流程

`资料入库 → AI提取候选 → 逐项核对原文 → 核对权威党史 → 编辑复查 → 运行校验 → 发布`

发布前运行：

```bash
npm run build:history
npm run validate:history
npm run eval:history
```

校验或评测失败的案例不得进入问答检索。验收门槛为史料覆盖率 100%、前 3 案例命中率大于 85%、引用准确率大于 95%、无关问题强行类比率低于 5%。外部链接可访问性和权威史料内容需要在编审时实际打开检查；自动测试只验证来源域名和本地原文锚点，不用网络结果替代内容审核。
